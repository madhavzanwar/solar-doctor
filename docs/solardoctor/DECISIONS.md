# Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-11-04 | Python package renamed `axalon` -> `solardoctor` (kept, not reverted). | Backend suite is at exact parity with the Axalon baseline (632 pass, same 10 weight-dependent failures). `AXALON_*` env vars are mirrored to `SOLARDOCTOR_*` at import time. |
| 2 | 2026-11-04 | Work and push on branch `claude/practical-dirac-fddnwu`, not `main`. | The session is restricted to that branch; the prompt's "push to main + tag" is deferred to the user. |
| 3 | 2026-11-04 | `/api/v1` is canonical; unprefixed routes stay as hidden deprecated aliases. | Existing tests and the legacy Next.js site use unprefixed paths. |
| 4 | 2026-11-04 | `ml/` -> `ml/thermal/` (package `ml.thermal`). | Leaves room for `ml/rgb` and `ml/forecast`. |
| 5 | 2026-11-04 | Thermal weights are not in git; `scripts/fetch_weights.py` pulls from HF; `ENABLE_THERMAL=false` by default in `.env.example`. | The LFS object cannot be fetched from this sandbox and no `HF_TOKEN` is available; upload is pending. |
| 6 | 2026-11-04 | Stripped the `best.pt` LFS pointer (`ml/checkpoints/best.pt`) from local history with `git filter-branch` before the first push. Backup ref: local `backup/pre-lfs-strip`. | GitHub rejects pushes whose history references an LFS object the repo does not hold (GH008), and the prompt forbids pushing the weights into our LFS. All other Axalon history/authorship is preserved; commit hashes differ from upstream. (Superseded by #7: the upstream history was later removed entirely and the local backup ref deleted.) |
| E1 | 2026-11-05 | Alert-route clash resolved by path, not by renaming Axalon's: Axalon keeps `POST /api/v1/alerts/test` (inspection-fault notification test, `routers/alerts.py`); the ported SolarPulse telemetry alerts are `GET /alerts`, `GET /alerts/{id}`, `PATCH /alerts/{id}/resolve` (+ `/anomaly/*`) in `routers/physics_alerts.py`, backed by table `plant_alerts`. | The path/method shapes do not overlap, so all existing Axalon alert tests stay green and the cloned frontend's `alertsApi` works unchanged. Two routers share the `/alerts` prefix; write policy differs (Axalon test = admin, plant alerts = operator+). |
| E2 | 2026-11-05 | SolarPulse `Plant` + `PlantConfig` are one `plants` table (`dc_kw`, `ac_kw`, `lat`, `lon`, `tz`, `tilt`, ...). API keeps SolarPulse names (`capacity_kw`, `inverter_capacity_kw`, `latitude`, ...) via read aliases; `/plants/{id}/config` stays a separate resource over the same row. | Matches the Phase E column list while keeping the frontend contract. |
| E3 | 2026-11-05 | Park-Plant 1:1 = `plants.park_id` unique FK -> `parks.id` (nullable, ON DELETE SET NULL); `Park.plant` backref. | Avoids ALTERing Axalon's `parks`; inspections/faults/work orders reach a plant through `plant.park`. |
| E4 | 2026-11-05 | No trained forecast model is shipped. Without an artifact the API serves `model_name="physics_baseline"` (deterministic pvlib/PVWatts); the probabilistic endpoint serves `physics_scenario_simulated` (SolarPulse's heuristic cloud wave, labelled SIMULATED). SolarPulse's `np.random` "development_fallback" noise was dropped. | No real plant data was available to train on; never present synthetic-trained output as a measured accuracy. `python -m ml.forecast.training.train` is ported and unit-tested; artifacts load from `ml/forecast/artifacts/models/`. |
| E5 | 2026-11-05 | Mock weather (no `SOLARDOCTOR_WEATHER_API_KEY`) is returned with `source="mock"` and "(Simulated)" condition text and is never used as an irradiance input to the physics/ML layers (clear-sky is used instead). NASA POWER hourly fetch + `weather_cache` added. | Mock weather is invented data. |
| E6 | 2026-11-05 | Diagnosis revenue uses the plant's `tariff_inr_kwh` (`currency="INR"`). With no tariff nothing is priced: `currency="unset"`, `financial_impact_per_day=0.0` and `financial_assumption` explains it (SolarPulse's $0.08/kWh default survives only in the golden-tested engine's default args, never via the API). `/diagnosis/diagnose` and alert diagnosis return 422 when expected/actual power cannot come from the request or real telemetry; SolarPulse's capacity*0.75 / *0.65 substitutes and the 750 W/m2, 32 C, 48 C telemetry defaults are not used. Soiling in forecasts keeps SolarPulse's assumed 7 days since cleaning (documented assumption). | Product is INR-centric; no invented tariff. |
| E7 | 2026-11-05 | SCADA WebSocket is `/api/v1/ws/scada/{plant_id}` on its own router and authenticates itself (`api_key`/`token` query or Authorization header) because HTTP middleware does not run for websocket scopes. SolarPulse's mock-telemetry ingestion worker was not ported (fabricates readings); simulated telemetry belongs to `make seed`, labelled SIMULATED. | Fail-closed auth for the stream; no invented data paths. |
| E8 | 2026-11-05 | QA fixes (REVIEW_physics): weather API key is redacted everywhere (provider errors are re-raised as `WeatherAPIError` with status only); plant `timezone` validated against zoneinfo, name/location length-bounded, `GET /plants` limit 1..500; batch SCADA ingest capped at 1000 rows with per-plant batched adapter lookups and one checkpoint write; duplicate park link IntegrityError -> 409; WebSocket accepts credentials via Authorization header, `Sec-WebSocket-Protocol: solardoctor.bearer, <token>`, or first message `{"type":"auth","token":..}` (offer `solardoctor.auth-first`), plus the legacy `?token=`/`?api_key=` query (ends up in server/proxy access logs: avoid in production). | Closes M1, M2, m1, m2, m4-m7. |
| E9 | 2026-11-05 | Open, deliberately not fixed: (m3) plants/telemetry are not scoped to Axalon projects, so any viewer in users mode sees all plants; scope via `plant.park -> project_id` when Park links are mandatory. (m8) The Timescale hypertable branch of migration 0011 is untested (no extension available); only its two ALTERs were run on plain PostgreSQL by QA. | Logged per coordinator instruction. |
| E10 | 2026-11-05 | Round-2 QA fixes: (F1) `harden_http_logging()` attaches a redacting filter to the httpx/httpcore/urllib3 loggers and, once, sets them to WARNING when a weather client is built, so the key stays out even if INFO logging is re-enabled. (F2) The diagnosis telemetry fallback needs BOTH power values from the request or BOTH from telemetry; telemetry must be <= 24 h old (`SOLARDOCTOR_DIAGNOSIS_MAX_TELEMETRY_AGE_H`), daylight (expected >= 5 % of AC rating), and not SIMULATED unless `allow_simulated=true`; `telemetry_ts`/`telemetry_source` are returned and persisted (two nullable columns added to the not-yet-released 0011 `diagnoses` table). (F4/F5) `skip` <= 1,000,000, plant kW <= 1e7, expected/actual >= 0. | Closes F1, F2, F4, F5. |
| E11 | 2026-11-05 | Golden-test data edit (F7): in `tests/backend/physics/golden_cases.py` the diagnosis comparison drops response keys that exist only in the SolarDoctor port (`currency`, `financial_assumption`, `telemetry_ts`, `telemetry_source`) before comparing with the SolarPulse original, which has no such fields. No expected value was changed and every SolarPulse field is still compared; the golden JSON was not regenerated. | Additive fields must not fail a parity check against code that predates them. |
| E12 | 2026-11-05 | `/forecast/{id}/summary` kWh now uses the real timestep: median positive gap between forecast timestamps (fallback 1 minute with <2 distinct timestamps), `kWh = sum(kW) * dt_hours`. SolarPulse divided by 60 (assumed 1-minute spacing), understating 15-minute data 15x. At exactly 1-minute spacing the result is identical. No golden test covered this function (golden cases cover only pure postprocessing/diagnosis/weather helpers), so no expected value changed; new tests in `test_forecast_summary_spacing.py` cover 1/5/15/60-minute, irregular and single-record series and a hand-computed example. With forecasts generated ad hoc at irregular times the median gap is only an approximation; a sum over a regular grid is the intended use. | Energy totals must not depend on an unstated sampling assumption. |
| 7 | 2026-11-05 | The AxalonSystems commit history was removed: the base import is a single commit with only our history above it. Upstream's MIT copyright line stays in `LICENSE` and an attribution entry in `THIRD_PARTY_NOTICES.md`. | The upstream authors were not part of this project; MIT requires keeping the copyright notice but not the commit history. All file contents are byte-identical to before the rewrite. All commit hashes changed: re-clone. |
