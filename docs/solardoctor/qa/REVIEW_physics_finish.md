## Findings (severity-ranked)
- MEDIUM, frontend: 422 body detail is an object ({status, message}). frontend/src/lib/api/errors.ts messageFromBody only reads string/array detail or top-level message, so users see the statusText ("Unprocessable Entity") not the explanation. Callers that hit it for the PVDAQ plant: dashboard/performance (loadProbabilistic runs on plant select/tab, so the page shows a dash-error immediately for that plant; handleGenerate), dashboard/plants/[id] (handleGenerate), alerts sandbox (only if no values; it always sends values so it works, and produces a diagnosis from caller numbers). Not a crash; a vague error. Report to sd-frontend: read detail.message and/or detail.status === "baseline_unsupported_for_trackers" and render a labelled "not supported for single-axis trackers" state; do not show Generate on such plants.
- MEDIUM, design: the marker is the only source of truth and lives in free-text `location`. Detection is an exact, case- and whitespace-sensitive substring: uppercased, double-spaced, or differently-cased marker is NOT flagged (tested). Prose such as "Tracker Farm, single-axis tracker site" is correctly not flagged. PUT /plants/{id} (operator role) with a new location silently strips the marker (tested: forecast generate then returns 200 with an invalid fixed-tilt baseline); anyone can also add the marker to disable a fixed plant. Acceptable for a demo with one importer-created tracker; for production add a mount/tracking column (migration) and have is_tracker_plant read it. Interim: PlantUpdate could refuse to drop/alter the marker.
- LOW, currency: GET /diagnosis/plant/{id} derives currency from the CURRENT tariff, not the one used at diagnosis time (table has no currency column). Repro: diagnose a plant with no tariff (stored 0.0, 'unset'), then PUT tariff_inr_kwh=6 -> listing shows that row as currency INR, financial_impact_per_day 0.0, no assumption text, i.e. "INR 0 loss"; changing tariff later relabels old values and reports them in the new rate's currency. Fix needs a currency column (sd-backend/architect).
- LOW: GET /diagnosis/taxonomy still contains "($/kW)" (golden-pinned). Frontend alerts page renders only title/urgency/description/error codes, so it is not visible in the UI; API consumers see it. Acceptable; record as known.

Consistent with the brief's author policy (caller values are not baseline output); note that a user can still get a deficit-style diagnosis for a tracker by typing numbers (alerts sandbox does).
