## Findings (severity ranked)
1. HIGH (CI, outside the diff, sd-architect): ci.yml sets workflow-level `ENABLE_THERMAL: "false"` (also on origin/main). Once the weights fetch succeeds the 10 weight tests run with thermal disabled and fail: repro `ENABLE_THERMAL=false pytest $(grep -v '^#' tests/weights_required.txt)` with best.pt present -> "RuntimeError: Thermal detection is disabled". Today CI is green only because the fetch fails/deselects. Fix: in the pytest step, export ENABLE_THERMAL=true when best.pt exists (and keep false otherwise). Must be fixed before this fetch is relied on in CI.
2. MEDIUM: `ml/thermal/checkpoints/best.pt.part` is not gitignored (`git status` shows it untracked; `git add -A` mid-download would stage up to 114 MB). Add `ml/thermal/checkpoints/*.part`.
3. MEDIUM (defence in depth): urllib's redirect handler forwards `Authorization` cross-host (reproduced: redirect_request keeps the header). Token is attached only when the initial URL is HF, so practical exposure needs an HF URL that redirects off-HF (not default; HF CDN hosts are *.hf.co). Fix: custom redirect handler that strips Authorization when the new host is not HF; or refuse non-https and non-HF hosts when HF_TOKEN is set. Also the default Space needs no token; consider not sending it at all for the fallback source.
4. LOW: pickle risk. Ultralytics 8.4.202 loads with weights_only=False unless ULTRALYTICS_SAFE_LOAD is set (default off), so loading best.pt runs pickle code; the SHA pin is the only defence. Backend only loads the fixed DEFAULT_WEIGHTS path (no user-supplied path; weights_path only a constructor arg, unused by routes); model_info uses an inert unpickler. Suggest setting ULTRALYTICS_SAFE_LOAD=1 in the thermal loader if the checkpoint loads under it (not tested by me). `--sha256`/`--url`/SOLARDOCTOR_THERMAL_URL let the caller change the pin: accepted as operator-controlled; `--dest` unrestricted and `file://` URLs accepted (local operator only). TOCTOU: file is hashed, then replaced atomically; a later load re-reads without re-verifying (skip-path verifies, but a local attacker with write access to the dir can swap between fetch and load). Rated low; same-user threat.
5. LOW: truncated downloads (connection closed early, no exception from read(n)) yield a hash mismatch, so the partial is deleted and resume never helps for that case; the same URL is not retried. Reliability only. No tests for: Range 206 with wrong offset, 416 handling, redirects, partial then network error keeps `.part`, env URL, `--force`, HF_TOKEN redirect.
6. LOW: CI's `-s best.pt` check is a non-empty test, not a hash test; a stray file would suppress deselection. In clean CI checkouts moot. CI still pip-installs huggingface_hub, no longer needed by the script.
